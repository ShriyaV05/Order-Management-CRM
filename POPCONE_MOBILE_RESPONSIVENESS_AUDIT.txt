1. EXECUTIVE SUMMARY & OBJECTIVE
================================================================================
The POPCONE Orders & Sales CRM is a single-page web application (SPA) serving as
the operational backbone for order management, inventory control, and revenue
analytics. Ashish, the primary stakeholder, operates the CRM predominantly from
his mobile smartphone. 

Currently, while desktop/laptop viewports (1366x768 and 1920x1080) deliver an
optimal experience with multi-column glassmorphic cards and sticky summaries,
the mobile smartphone experience (< 768px) suffers from severe architectural
friction:
  1. Critical information is pushed off-screen due to 1326px wide fixed tables.
  2. Modals (especially Edit Order) exhibit severe horizontal clipping where
     entire input columns (Phone, District, Order Source) are inaccessible.
  3. Action buttons in modals (such as "Mark as DISPATCHED") spill outside the
     viewport boundaries.
  4. On the New Order page, the Order Summary and "Create Order" button are
     pushed over 1900px down the page below 4 tall flavour cards and combo
     banners, making order creation cumbersome.
  5. Navigation requires reaching to the extreme top-left corner to open a
     hamburger drawer, which on mobile displays icons without text labels due
     to conflicting media query rules.
  6. Dashboard and Analytics KPI cards stack in a single column with excessive
     padding, forcing hundreds of pixels of unnecessary vertical scrolling.

The objective of this project is to implement true responsive adaptation:
  - ONE single unified codebase with responsive layouts for all viewports.
  - Zero changes to the existing desktop/laptop design, styling, and interactions.
  - Zero changes to backend business logic, Turso database schema, or stored records.
  - High-efficiency mobile layouts prioritizing rapid thumb reachability, compact
    information hierarchy, eliminated horizontal overflow, and tactile controls.

----------------------------------
Current Status:

4.2 NAVIGATION & APP SHELL (#main-sidebar, .top-header, .main-wrapper)
-----------------------------------------------------------------------
Current Status:
  - Below 768px: `.sidebar` has `position: fixed; transform: translateX(-100%); width: 260px !important;`
  - Toggle: Hamburger button in `.top-header` toggles `.sidebar.mobile-open`.
Usability Hotspots:

    the way to the top-left corner (y: ~32px) to hit a 38x38px hamburger icon,

    to close. This requires 2-3 taps per navigation event.
  - Top Header Spacing:
    `.top-header` has fixed `height: 64px; padding: 0 28px;`. On 360px phones,
    the hamburger button (38px), page title ("Inventory & Stock History" = 220px),

Selectors Involved:

5. COMPREHENSIVE TECHNICAL AUDIT
================================================================================

5.1 CSS ARCHITECTURE & MEDIA QUERIES BREAKDOWN
----------------------------------------------
The file `static/css/styles.css` (4,779 lines) currently contains 11 media queries:
  1. @media (max-width: 600px): Login overlay card sizing.
  2. @media (max-width: 400px): Small screen login card adjustments.
  3. @media (max-width: 900px): Collapses sidebar to 72px and hides nav labels.
  4. @media (max-width: 680px): Edit combo options grid adjustments.
  5. @media (max-width: 768px): Positions sidebar off-canvas with translateX(-100%).
  6. @media (min-width: 1150px): 5-column single-row alignment for Dashboard & Analytics KPIs.
  7. @media (max-width: 1080px): Collapses New Order layout to 1 column.
  8. @media (max-width: 640px): Content scrollable padding (12px) & New Order form span overrides.
  9. @media (max-width: 640px): Orders search row column stacking.
 10. @media (min-width: 1050px): 4-column single-row alignment for Inventory stock cards.
 11. @media (prefers-reduced-motion: reduce): Accessibility animation suppression.

Key Finding:
The existing media queries were added opportunistically at different breakpoints
(900px, 768px, 680px, 640px, 600px, 400px) rather than following a unified,
systematic mobile-first or desktop-isolated breakpoint scale.
Crucially, the rule at 900px (`.nav-text { display: none; }`) bleeds directly into
the 768px mobile drawer rule, causing the invisible label bug.

5.2 FIXED WIDTHS, FLEXBOX, GRIDS & OVERFLOW HOTSPOTS
----------------------------------------------------
  - `#app-container`: `width: 100vw; height: 100vh; overflow: hidden; display: flex;`
    Correctly prevents body overscroll on desktop, but on mobile requires proper
    `height: 100dvh` (dynamic viewport height) to account for iOS Safari and
    Android Chrome URL bars appearing/disappearing.
  - `.content-scrollable`: `flex: 1; overflow-y: auto; overflow-x: hidden;`
    Child elements with fixed `scrollWidth` (like tables at 1326px) cause either
    unwanted horizontal drag or severe clipping.
  - `.crm-table`: `white-space: nowrap; width: 100%;`
    On desktop, `nowrap` prevents messy multi-line cell breaks. On mobile, it
    forces the table to expand to 1326px, breaking narrow viewports.
  - `.form-group.span-2`: Hardcoded to `grid-column: span 2;` inside `.form-grid`.
    Forces 2-column widths inside modals even on 360px screens.

5.3 JAVASCRIPT VIEWPORT HANDLING & DOM MANIPULATION
---------------------------------------------------
In `static/js/app.js`:
  - L2015: `if (window.innerWidth <= 768 && sidebar) { sidebar.classList.remove('mobile-open'); }`
    Automatically closes the sidebar on tab navigation.
  - Sidebar collapsed state preference is stored in `localStorage.getItem('popcone_sidebar_collapsed')`.
    Correctly guarded by `window.innerWidth > 768`.
  - No JavaScript hardcoded pixel widths are injected into DOM styles.
    All sizing is governed by CSS classes, making the application 100% cleanly
    adaptable via isolated media queries without altering JS business logic.

5.4 TOUCH TARGETS, FORM CONTROLS & VIRTUAL KEYBOARD BEHAVIOUR
--------------------------------------------------------------
  - Touch Target Guidelines: Apple iOS HIG and Google Material Design require
    interactive elements to have a minimum touch target size of 44 x 44px (or 48 x 48px).
  - Current Deficiencies:
    * Modal close buttons (`.btn-close-modal`): 28 x 28px (too small for thumb).
    * Quantity steppers (`.btn-qty`): 32 x 32px.
    * Table row action buttons: 30 x 30px.
    * Password toggle button: 28 x 28px.
    * Date and select inputs: 38px height (should be 44px on mobile).
  - Virtual Keyboard:
    * iOS Safari zooms in automatically on `<input>` if `font-size < 16px`.
    * Current `.form-control` has `font-size: 13.5px` or `14px`. On iPhone,
      tapping any input triggers an unwanted page zoom!
    * Fix: Ensure inputs have `font-size: 16px` on mobile screens to prevent
      browser auto-zoom while maintaining crisp visual presentation.

6. DESKTOP PRESERVATION STRATEGY (ZERO-REGRESSION GUARANTEE)
================================================================================
A core mandate of this project is that the existing desktop and laptop experience
must remain 100% UNTOUCHED and PRESERVED.

Isolation Architecture:
  1. ZERO Unscoped CSS Edits:
     No global changes to existing desktop classes (`.sidebar`, `.top-header`,
     `.kpi-grid`, `.inventory-stock-grid`, `.new-order-layout-grid`, `.modal-container`,
     `.crm-table`) will be made outside of media queries.
  2. Mobile Scope Isolation:
     All mobile-specific overrides will be strictly wrapped inside:
       `@media (max-width: 767px) { ... }`
     And small phone edge cases inside:
       `@media (max-width: 480px) { ... }`
  3. Tablet Scope Isolation:
     Tablet adjustments will be strictly wrapped inside:
       `@media (min-width: 768px) and (max-width: 1024px) { ... }`
  4. Desktop Base Preservation:
     Any rule targeting screens `>= 1025px` will remain entirely as written today.
     The single-row 4-column stock grid (`@media (min-width: 1050px)`) and single-row
     5-column KPI grid (`@media (min-width: 1150px)`) will remain active on desktop.
  5. Feature Parity & Single Codebase:
     No duplicate HTML pages or separate endpoints. The exact same DOM nodes will
     adapt responsively via CSS Grid and Flexbox reflows.

7. TABLET RESPONSIVENESS STRATEGY (768px - 1024px)
================================================================================
Tablet viewports (such as iPad in portrait at 768x1024 or landscape at 1024x768):
  - Sidebar: Compact 72px icon sidebar with tooltip hovers, leaving ~700px-950px
    for main content.
  - Dashboard & Analytics KPIs: Clean 3-column / 2-column or 4-column auto-fit
    grid (`repeat(auto-fit, minmax(220px, 1fr))`) without awkward orphans.
  - Inventory Stock Grid: 2-column x 2-row grid (`repeat(2, 1fr)`).
  - New Order: 2-column layout preserved where tablet width >= 900px, or 1-column
    with sticky summary where < 900px.
  - Tables: Horizontal scrolling container with subtle fade indicators on the
    edges to signal scrollable content.
